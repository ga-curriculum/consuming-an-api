## API Keys

API keys are a way for API providers to control access to their API. They are a unique identifier that is used to track and control how the API is being used. API keys are usually a long string of random characters that are generated by the API provider, and are usually passed as a query parameter in the URL when making a request to the API.

Since API keys are a unique identifier they should be kept secret. If someone else gets a hold of your API key they can use it to make requests to the API under your identity. If you are paying for the API this can result in charges on your account that most companies will hold you responsilbe for. If you are using an API key in your application you should never commit it to your repository. Instead you should store it in an environment variable and access it from there.

## Optaining an API Key - OMDB API

For this lesson we are going to use the [OMDB API](http://www.omdbapi.com/). This API allows us to search for movies and get information about them. To use this API we need to get an API key. Let's complete the following steps:

- Go to the [OMDB API](http://www.omdbapi.com/) website
- At the top of the page click on the "API Key" link
- Select the "FREE!" plan
- Fill out the form and click "Create Account"

> 📚 Note the rate limit for the free plan is 1000 requests per day.

Once you have created your account your API key will be sent to the email you used to sign up. Visit your email and copy the API key.

> You might have to activate your API key by clicking on a link in the email. Follow all instructions given in the email. As noted third party APIs are created by someone else so changes in how we use the API can happen at any time. When in doubt always follow the API documentation or instructions.

### Keep it secret, keep it safe

We have collected our very first API key. Now what? We need to keep it secret. Luckily the worst thing that can happen if someone gets a hold of our OMDB API key is they can run our over rate limit or get our account banned. Not good but not the end of the world. However we should still treat it as if it was a password and keep it secret.

When developing an application we should never commit our API keys to our repository. Instead we should store them in an environment variable and access them from there. This way we can keep them secret and not have to worry about them being exposed in our code.
